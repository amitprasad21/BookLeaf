# Verification: API-2 Authentication, Role Guards and `GET /me` (2026-10-18)

**Scope:** task API-2 on branch `feature/api-auth`. No new packages. Tokens and passwords were never printed.

## 1. Approach check

The installed supabase-js/auth-js (2.117.2) declares `getClaims(jwt?, options?)`. Its documentation: it verifies against `/.well-known/jwks.json` (cached) for asymmetric keys, otherwise it asks the Auth server, and it rejects expired tokens. Decision D-022.

## 2. Offline tests (`npm test`): 12 files, 69 tests pass

New `test/auth.test.ts` (fake verifier):
- No token → 401 on `/me`, `/admin/tickets` and an unknown path (route existence isn't revealed).
- Malformed headers (Basic, bare `Bearer`, non-JWT, > 4 KB) → 401.
- Unknown token → 401 with a "sign in again" message.
- Valid user without a profile → 403.
- Verifier outage → generic 500, internal detail not leaked, logged.
- Health and API docs stay public.
- `?role=admin&userId=…` in the query is ignored.
- `/me` shapes for an author (with author summary) and an admin (`author: null`).
- Author on `/admin/*` → 403 and admin on `/author/*` → 403; the right role reaches the namespace (404 until routes exist).

Updated: `env.test.ts` (Supabase values required outside tests; https only), `errors.test.ts` and `logging.test.ts` (unknown `/api/v1` paths now need a token to reach 404).

`npm run check` (format, lint, OpenAPI lint, typecheck, tests, build): **exit 0**. `openapi.yaml`: `/me` documents its 403, and `AuthorProfile.city` is nullable to match the database.
