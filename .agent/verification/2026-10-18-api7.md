## 1. What was built

- **Migration** `supabase/migrations/20261018120000_admin_reply_function.sql` adds `public.admin_send_reply`:
  - `security invoker`, `search_path = ''`; `EXECUTE` for `authenticated` only.
  - In one transaction: lock the ticket, refuse resolved/closed tickets and unknown drafts, insert the message as `auth.uid()`, then set `first_response_at`, the status and `resolved_at`.
  - The rollback is in `supabase/rollback/`. `check:db` probes the function: it must exist and refuse a non-admin call.
- **`packages/shared/src/schemas.ts`:** `AdminReplyRequestSchema` (trimmed body 1–5,000, `draftId`, `statusAfter` in_progress|resolved, default in_progress) and `MessageBodyRequestSchema`.
- **`admin-repository.ts`:**
  - `sendReply` (the RPC) maps `P0002` → 404, `reply_requires_reopen` → 422 and `draft_not_found` → 400 on `draftId`; anything else becomes a generic error.
  - `listNotes` returns null for an unknown ticket.
  - `addNote` is an RLS insert as the caller; the FK doubles as the existence check (23503 → 404).
- **Routes:**
  - `POST /admin/tickets/:id/messages` → 201 `ThreadMessage`, audited `ticket.reply_sent`, plus `ticket.status_changed` with `via: reply` when the status moved.
  - `GET` / `POST /admin/tickets/:id/notes`, with `ticket.note_added` audited as `{ noteId }`.
- **Test fakes:** `adminRepository(overrides)` lets a test implement only what it uses, and `recordingSupabase` now records `rpc()` calls and canned errors.
- **`openapi.yaml`:** reply rules (422, 400 draft, transaction, audit), note audit wording, 400 on listing notes.
- **Decision:** D-027.
