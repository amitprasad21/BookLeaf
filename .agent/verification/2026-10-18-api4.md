## 1. What was built

- `packages/shared/src/schemas.ts`: strict request schemas shared with the frontends.
  - Create body: `bookId` (`BK…` or null), subject 5–150, description 20–5,000, optional attachment name (.jpg/.jpeg/.png/.pdf).
  - List query: `status` as a comma list, `page`, `pageSize` ≤ 100.
  - `ticketId` must be a UUID.
- `backend/src/modules/tickets/`: an author-scoped repository with an explicit `author_id` filter (RLS applies on top), `mapPostgrestError`, and the author serializer (allowlisted fields; admin replies signed "BookLeaf Support", A-07).
- `backend/src/db/system-writer.ts` (`appendAuditEvent`) and `modules/audit/service.ts`. A failed audit write is logged and never fails the request.
- `middleware/rate-limit.ts`: per user, 5 per 10 min and 20 per day; failed requests don't count.
- ESLint `no-restricted-imports` confines `db/system-writer` to `ai/**`, `modules/audit/**` and the bootstrap. Probe: an import added to `modules/tickets` failed lint; the same import in `modules/audit` passed. The probe was removed afterwards.
- `SUPABASE_SECRET_KEY` is now required by the server outside tests (`env.test.ts`).
- Decisions: D-024. `openapi.yaml`:
  - `getAuthorTicket` documents 400 for a malformed id.
  - `CreateTicketRequest` patterns and the ownership/limit notes are added.
  - `senderName` describes both views.
  - `attachmentName` is required (nullable) in the detail.

## 2. Offline (`backend/test/tickets.test.ts`, 18 tests). Suite total: 15 files, 106 tests pass

- **Create:** 201 with a `Location` header and the detail DTO (`open`, `hasAdminReply: false`, empty thread). Text is trimmed. `bookId: null` is accepted (General / Account Level).
- **Ownership:** BK003 (Rohit's) and BK999 (unknown) get the identical 400 on `bookId`; nothing is stored.
- **Validation:** short subject or description, missing `bookId` and a `.exe` attachment each give 400 `VALIDATION_FAILED` naming the field. `authorId`, `status` and `priority` in the body are rejected.
- **Rate limit:** an invalid request doesn't count. 5 creates pass, and the 6th gets 429 `RATE_LIMITED` with `Retry-After` > 0.
- **Audit:** exactly one `ticket.created` event (`actorProfileId` = caller, metadata `{ bookId }`, no text). With a failing writer the ticket is still created (201) and the warning is logged.
- **List:** only the caller's tickets, sorted by newest activity (an admin reply moves a ticket to the top, and `hasAdminReply` becomes true). Status filter and paging give the right `meta`. Unknown status, `pageSize=500` and `page=0` → 400. An empty list has total 0.
- **Detail:** the thread is in order; the admin reply shows "BookLeaf Support" and the author's message shows "Priya Sharma". Another author's ticket → 404 `NOT_FOUND`; a malformed id → 400.
- **Contract:** summary and detail DTO keys equal the `openapi.yaml` schema properties exactly. There are no priority/category/AI/assignee/version/note fields.
- **`mapPostgrestError`:** `rate_limited` → 429; 23503 → 400 on `bookId`; 23514 → 400; 42501 → 403. Any other code becomes a plain error with no database message.
